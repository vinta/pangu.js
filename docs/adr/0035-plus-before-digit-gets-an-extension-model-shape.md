# A plus before a digit gets an extension model shape

Core keeps `CJK+N` as a signed number: `英文字母+9位數字` becomes `英文字母 +9 位數字`, just as `打+886這個號碼` keeps `+886` together. The sentence decides whether the plus joins two items. Add a `plus-digit` ambiguous shape under the extension's AI spacing toggle, following [ADR 0017](0017-ai-spacing-policy-stays-in-the-extension.md).

Use frozen `v1-en` from the [verified prompt experiment](../../scripts/prompt-experiments/plus-digit/results/20261023-first-shape/REPORT.md), with labels `signed-number`, `conjunction`, and `unsure`. Only `conjunction` inserts one ASCII space after the plus. Other labels, invalid answers, failed requests, an unavailable model, or disabled AI spacing retain core output.

The detector reuses core's `CJK_SIGN_DIGIT` on original text within one node. The settled text must still contain `CJK +N`, with exactly one ASCII space before the plus and none after it. Author-spaced forms and candidates split across nodes do not qualify. The extracted context must contain exactly one ASCII `+`, including inline siblings. The reader keeps the existing 120 UTF-16 units per side and `。！？；` boundaries. The user-provided ID sentence has two eligible targets because `；` separates their contexts.

`digit-plus` requires a digit before the plus; `plus-digit` requires CJK, so they cannot claim the same symbol. Every shape classifies original context and builds edits against the same settled text. The existing edit merger applies them together in descending position order. A negative lower bound and positive upper bound can therefore retain both signs: `在-50℃至+200℃` becomes `在 -50℃ 至 +200℃`.

Verified conjunctions include the user-provided ID format and [可樂旅遊's parent-child ticket](https://www.colatour.com.tw/C10G_DomTour/C10G_Q02_DisplayTicket.aspx?TicketRateNo=349). Sign controls include [領事事務局's phone prefixes](https://www.boca.gov.tw/cp-53-378-353fb-1.html), temperatures, score differences, and percentage changes. The [composed evaluation](../../scripts/prompt-experiments/plus-digit/results/20261023-composed-output/REPORT.md) passed both comparisons: 20/22 labels, 20/22 target spacing, and 19/21 complete excerpts. All 168 candidate sign attempts retained their spacing. The school ID-format and basketball headline remain conjunction misses; the shape does not promise to fix every conjunction.

Phase 2 replayed all 22 reviewed targets across 21 excerpts through the production content script, using saved HTML/CSS and stubbed gold labels. Chromium, Firefox, and WebKit matched every original input, target offset, and complete expected output, including the three excerpts with hyphen-digit companions. No case was dropped or changed. Re-preparing the corpus with production detectors preserved every scored field and frozen prompt; both component and composed gates passed again on the saved answers using production edits. This verifies integration without adding new model-accuracy evidence.

The npm package keeps its sign rule and the seed's rules-only expectation. No model policy moves into core, pangu.py, or pangu.go. Real digit-plus interactions and mixed conjunction/sign excerpts remain model-accuracy gaps; deterministic integration tests establish routing and edit composition only.
