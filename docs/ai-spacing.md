# AI spacing

pangu's rules read a hyphen-minus between a CJK character and a digit as an operator ([ADR 0015](adr/0015-hyphen-before-digit-reads-as-operator.md)), because at that shape no rule can separate a year range from a signed number: whatever it decides for `博客來-4%` it decides for `氣溫是-5度`. AI spacing restores the sign reading on the candidates where it is the right one, for extension users who turn it on. This document is how it is built. The decision to build it at all, and what that decision closed, is [ADR 0016](adr/0016-hyphen-before-digit-gets-a-model-layer.md). The API it runs on is described in [`prompt-api-reference.md`](prompt-api-reference.md).

## Contract

The rules flag the candidate, the model classifies its reading from an enum, and the rules insert or remove spaces deterministically per label. The model never emits text, which is what keeps [ADR 0009](adr/0009-nbsp-suppresses-spacing-never-rewritten.md) intact: the only byte AI spacing can ever remove is a space pangu itself inserted.

AI spacing is a late fix on top of a finished result, not a step the output depends on. The synchronous rules pass runs unchanged and its output is what the page gets; the model pass afterwards adjusts only the candidates it reads as signed numbers. With the model absent or unavailable, today's output stands; with the model slow, it stands until the answer arrives.

## Constraints

- **Zero-regression bar.** Control cases — the candidates the rules already get right — must never flip. A configuration that wins an ambiguous case at the cost of one control fails outright. Wins and flips are reported split, never blended into one accuracy number.
- **Latency target.** Under half a second warm per candidate, so a page of a few dozen candidates settles in seconds. Nothing enforces a page-level cutoff: a late answer applies when it arrives (decision 2).
- **Opt-in, extension-only.** No model dependency reaches the npm package. The extension feature-detects with `availability()` and degrades to rules-only, so the manifest floor stays at Chrome 99 and detection is a runtime check rather than a manifest bump.
- **zh is the measured envelope.** Every prompt variant and every corpus case behind AI spacing is Chinese, and the numbers carry no further. It nevertheless ships without a page-language gate; if ja or ko pages prove problematic, the gate candidates are `chrome.i18n.detectLanguage` (Chrome 99+, inside the manifest floor) with `documentElement.lang` as a pre-check.

## Decisions

1. **Sentence windowing: sentence-slice, not whole text node.** The `sentence` sent per flagged hyphen is a slice of the pre-spacing text node, cut at CJK sentence terminators (`。．！？；` and newline) around the hyphen, capped at roughly 120 characters per side when no terminator appears. The whole measured envelope is single short sentences and the system prompt frames its input as 整句話, so a paragraph blob is off-envelope in presentation, not merely expensive. The window is over pre-spacing bytes because that is what `find` needs for provenance.
2. **Budget: no deadline, and no dedupe.** One `CLASSIFY_CANDIDATES` round trip per ambiguous shape per batch, all of them awaited together with no deadline. A 30-second per-batch deadline shipped first (2026-09-01) and was dropped on 2026-09-02, because the one thing it bought — no visible text change more than 30 seconds after the rules pass — cost more than it was worth. A late answer was already safe: the compare-and-set in `applyLateFixes` drops any fix whose text node changed since it was flagged. The worker has no abort signal, so an abandoned batch still ran every prompt on the single-lane model and the deadline only discarded answers already paid for. A batch too large to finish inside the window never landed any fix, and the batch queued behind it inherited the delay. And every other timer in the codebase — the video-load fallback, the idle-callback timeout, the debounce max wait — caps how long to wait before doing the work; none discards work already done. The cost accepted in return: when the model is slow, a focused page shows a one-character shift late rather than staying unfixed. No result caching or candidate dedupe ships. Framework re-render churn re-classifies the same candidates, which is accepted: temperature-0 answers are deterministic, so the output stays stable and only battery is spent.
3. **Prompt source: an extension-local constant.** The extension and any experiment harness that measures prompts are separate things serving different purposes, so the extension carries its own copy of the winning prompt bytes and imports nothing. Duplicated bytes are the accepted cost of an extension that stands alone.
4. **Candidate scope: a single text node.** Only a tight `CJK-digit` shape inside one text node is flagged. Shapes split across two text nodes, where the hyphen and the digit sit on either side of an element boundary, are out: late-fix provenance across boundary spacing has no measured basis.
5. **Seam: two primitives on `BrowserPangu` that name no symbol.** Core owns mechanism, host owns policy. `onTextNodesSettled` is a nullable callback property receiving every text node text spacing read, as `{node, unspaced, settled}` records, unfiltered, fired once per batch at the batch tail. `applyLateFixes` takes compare-and-set writes, `{node, settled, data}`, one fix per text node per call, composing nothing. Neither primitive knows a hyphen, a label, or a model exists; every per-shape fact lives in the extension. The extension is the only assigner, and unassigned means nothing is captured, which keeps the npm build inert without a build flag. The seam stays a plain callback property rather than an event target or a hook registry, because there is one first-party subscriber in the same process. Subclassing and event dispatch were both considered and rejected as indirection, and subclassing carries a second problem: the extension consumes the UMD singleton `window.pangu`, so a subclass instance would bring its own observer and scheduler state.
6. **The shipping classifier carries no eval instrumentation.** No variant parameter, no per-variant session map, no label-bijection machinery, no presented-order support, no telemetry fields, no concurrency helper, no per-candidate correlation ids. Request and response arrays zip by index, order-preserved by a sequential loop. `PromptSpec.version` is the id of the measured prompt bytes, logged with the base session, not a switch.
7. **The options page talks to the model directly.** Extension pages are ordinary `chrome-extension://` documents and expose `LanguageModel`, so rendering a status line needs no service-worker round trip. This claim is graded [secondary] in the reference document and is not verified by an automated test; if it fails to hold, the options page renders its "unsupported" status rather than breaking, and a slim worker-message fallback stays unbuilt until real evidence calls for it.
8. **The seam was generalized on 2026-09-03, ahead of the second ambiguous shape.** It shipped on 2026-09-01 under hyphen-specific names, `onHyphenSpans` and `applyHyphenSignFixes`, on the reasoning that a generic name carrying a single shape for however long this ships alone costs more than the rename does later, since renaming one callback property and one method with the extension as the only assigner is mechanical. That reasoning deferred the rename until a second ambiguous shape earned a model, and the `+` brand-suffix reading is now planned as that shape ([ADR 0013](adr/0013-protected-word-list-removed.md), the open FIXME in `tests/shared/symbol-plus-sign.test.ts`), so the rename came due: adding it on hyphen-specific names would have meant a second core pair duplicating the capture, batch-tail, and write machinery per shape. The seam was generalized first, on its own, as a structural change with identical DOM output. The ambiguous-shape registry lives in the extension, which is where more than one entry will sit: a page-side `AmbiguousShape` (`kind`, `find`, `settle`, `isFix`, `edits`) whose hyphen instance is `hyphenSign` in `ai-spacing/hyphen-sign.ts`, and a worker-side `PromptSpec` whose hyphen instance is `hyphenPrompt` in `ai-spacing/hyphen-prompt.ts`, joined by nothing but `kind` and a label type. Both interfaces are declared together in `ai-spacing/ambiguous-shape.ts`, because types erase. The instances stay in separate modules because the content script and the service worker are separate bundles and object-literal properties do not tree-shake, so one merged object would ship prompt bytes to the page and the page-side scan regexes to the worker.
9. **Prompt API types come from `@types/dom-chromium-ai`.** The DefinitelyTyped package covers the ambient `LanguageModel` class, `Availability`, `CreateMonitor` with the `downloadprogress` event, the system-first `initialPrompts` tuple, `responseConstraint`, and both context-accounting spelling sets. It types `params()` as unconditionally present, so the classifier keeps runtime guards for it rather than trusting the type.

## Component specification

### Batch tail (`src/browser`, on `BrowserPangu`)

`unspaced` is captured inside `applyTextNodeSpacing`, in the `apply-text-spacing` branch, right before `spacingText` runs and only while `onTextNodesSettled` is assigned: that is where the pre-spacing `textNode.data` is still in hand, and the tight original is the only thing that identifies which spaces the rules wrote. Not at the method's entry, because `decideTextNodeSpacing` can return `trim-leading-space` ahead of `apply-text-spacing` in the same verdict list, and an entry-point capture would hand the classifier a sentence with one more leading space and `at` off by one. Text nodes that got only a trim or a `prepend-space` are absent from the list, because text spacing never ran on them. Nothing else is filtered: a text node text spacing left unchanged is still handed over, because whether an unchanged text node matters is the host's policy, not core's.

`settled` waits for the batch tail, after `spacingTextNodes` completes and all boundary writes have landed, because boundary spacing runs after each text node's text spacing and mutates the same nodes: `respaceCurrentTail` rewrites the current tail, `append-current` appends a space, `prepend-next` prepends to an already-processed node. A snapshot taken in the apply-text-spacing branch would be stale on any text node that also receives a junction space, which is a common page shape, and the compare-and-set in `applyLateFixes` would then silently drop those fixes.

`flushSettledTextNodes` fires `onTextNodesSettled` once per `schedule()` batch, whenever the captured list is non-empty, handing over one `SettledTextNode` per text node as `{node, unspaced, settled}`. A batch is one task closure, so it never splits across idle slices; the unsettled list is a local of `spacingTextNodes`, threaded through `applyTextNodeSpacing` and the flush, so two batches can never share one. The list arrives in reverse document order, since `DomWalker.collectTextNodes` collects reversed for boundary spacing; the order carries no meaning for the consumer, which reads each record's own `node`. The callback fires on both the `requestIdleCallback` path and the synchronous fallback, and on every pipeline entry: the initial sweep, mutation batches, manual spacing from the popup, and `<title>`, where it is deterministic because separator labels change nothing.

### Late fix (`src/browser`, on `BrowserPangu`)

`applyLateFixes(fixes)` writes each `LateFix` whose text node still holds the bytes the fix was computed from: per fix, `node.isConnected` and `node.data === fix.settled`, and the fix drops silently otherwise. The comparison target is the caller's own snapshot rather than `lastWrittenData`, which a later batch may have advanced; equality also pins every position, so core needs no re-scan and never re-derives what the fix means. One fix per text node per call, and no composition: a second fix on the same text node would fail its own `settled` check and drop, so composing several edits into one write is the caller's job.

The write goes through `schedule()` and records its result in `lastWrittenData`, so the MutationObserver reads it as pangu's own write. Routing it through the same seam as every other spacing write is deliberate — the late fix is text spacing, one system, one seam — and it carries two costs. On a hidden tab `requestIdleCallback` stops firing, timeout included, so the fix waits for focus, in the same beat dynamic-content spacing already waits; the staleness window runs until focus, so more fixes drop and their model calls are spent. And a label can be logged with the page still visibly unchanged, which is a waiting tab rather than a bug. Correctness is seam-independent: the compare-and-set runs at write time, and the rules are a fixed point on fixed text.

### Ambiguous shapes (`browser-extensions/chrome`)

The hyphen sign is the first entry and today the only one, `hyphenSign` in `ai-spacing/hyphen-sign.ts`. `find` scans `unspaced` for the tight `CJK-digit` shape and returns one `CandidateMatch` per hit, carrying `sentence` (the pre-spacing slice, with `at` recomputed relative to it, always containing the preceding CJK character) and the hyphen's ordinal — which `-` this is, counting hyphen-minus characters in the pre-spacing text node.

`settle` resolves a match against `settled`. The ordinal is the pre-to-post bridge, valid because spacing writes only add or move spaces and never hyphens (the only character conversions are middle dots and the CJK colon); it stays internal to the ambiguous shape, between `find` and `settle`, and never goes on the wire. A match settles only if the settled bytes actually show the inserted gap: the hyphen at that index, followed by a space, followed by a digit. Otherwise `settle` answers `null` and the match is dropped. That check is self-verifying provenance — hidden-boundary suppressions and author-spaced originals drop out naturally — so the late fix can only ever remove a byte pangu wrote.

`isFix` accepts the one label `signed-number`, and `edits` deletes the single space after the hyphen at the settled index, as one `TextEdit` rather than a composed string. The space before the hyphen stays: `是 - 5` becomes `是 -5`.

The extension carries its own copy of the `CJK` character class rather than importing `src/shared/index.ts`, for three reasons: the content script loads `pangu.umd.js` as a separate classic script and the UMD global does not expose `CJK`; a content script cannot be an ES module, so it cannot import the ESM build at runtime; and bundling `src/shared` into the content script would risk a second copy of the engine beside the UMD one, because that module ends with `export const pangu = new Pangu()`. A vitest case in `tests/extension/hyphen-sign.test.ts` asserts the copy equals `CJK` from `src/shared/index.ts`, so drift fails CI. Same precedent as decision 3: duplicated bytes are the price of an extension that stands alone.

`range-or-separator`, `unsure`, and errored candidates leave the rules output untouched.

### Content script (`browser-extensions/chrome`)

Reads `is_enable_ai_spacing` through `getSettings()` at injection. When on, it assigns `window.pangu.onTextNodesSettled` before calling `autoSpacingPage()`, so the initial sweep is captured. Per batch it runs `find` over `unspaced` and `settle` over `settled` for every registered ambiguous shape, and returns before sending any message when no shape found a candidate: core hands over every text node text spacing read, so most batches carry nothing to ask about, and asking only for the shapes that found something is what keeps worker wakes, and the multi-second cold-start `create()` behind them, down to the batches that can produce a fix. Each shape that found candidates gets one `CLASSIFY_CANDIDATES` carrying its `kind` and `[{sentence, at}]`, and all of them are awaited together with no deadline.

The first `{ok: false}` for any kind unassigns the callback: model absent, availability not `available`, any create failure, no prompt spec registered for that kind, or a `sendMessage` that throws because the worker is gone after an extension reload. Every kind's response is checked before anything is composed, so a no never lands half a batch. Unassigning both stops core from capturing later batches and stops any further worker wake, which is what "the first no is final for this page" now means on the generic seam.

Labels zip against the candidates by index. Every candidate whose label passes its shape's `isFix` contributes that shape's `edits`, collected per text node, because a text node can carry candidates from more than one ambiguous shape and core applies one fix per text node per call. `applyTextEdits` in `ai-spacing/ambiguous-shape.ts` applies a text node's edits to `settled` in descending index order, so an earlier edit cannot shift a later one's index, and each text node becomes one `LateFix { node, settled, data }`. `applyLateFixes` is called at most once per batch, only when the batch produced a fix.

### Classifier and service worker (`browser-extensions/chrome`)

Each ambiguous shape's `PromptSpec` carries its shipping prompt bytes in an extension-local constant file, tagged with the `version` that earned them: the system prompt, the markless question template (an untouched sentence, with the question pointing at the symbol by quoting the character before it), the display tokens, and the canonical menu order. `prompt-classifier.ts` holds the registry, keyed by `kind`, and keeps one base session per kind in a `Map<kind, Promise<LanguageModel>>`, since each shape's system prompt rides in its own session's `initialPrompts`. A session is created at `temperature 0` and `topK 1`, cloned per candidate through a sequential loop, and recreated when the MV3 worker wakes. What is cached is the promise rather than the session, so batches that arrive while one `create()` is in flight share it, and a rejected `create()` drops that kind's entry, because the model can arrive later through the options-page download. A message whose `kind` has no prompt spec registered answers `{ok: false}`, the same clean no the page gets for an absent model.

Any `create()` failure yields `{ok: false}` with no retry arm, which is a correctness decision rather than tidiness: the sampling knobs are extension-context Chrome 151+ while the manifest floor is 99, so a retry that dropped them would silently run model-default sampling on older Chrome — the exact drift that flipped control cases in the plain-page measurements. A context that cannot pin sampling yields no session at all.

There is no worker-side setting check. The content script is the gate, and behavior-until-refresh is the accepted `refresh_required` semantics every setting already has.

### Setting and options page (`browser-extensions/chrome`)

`is_enable_ai_spacing` defaults to `false` and lives in `DEFAULT_SETTINGS`, which `reconcileSettings` and the `chrome.storage.sync` schema pick up automatically. The toggle follows the `refresh_required` registration pattern, so there is no live-toggle plumbing. The options page gains a section with the toggle, a status line from `availability()`, and an explicit download button driving `LanguageModel.create({monitor})` — the download is browser-wide, and the page-context session is destroyed afterwards. There is no progress UI: the monitor callback logs the `downloadprogress` percentage and the status line's `downloading` state covers the visible feedback. A machine whose model is absent degrades silently to rules-only, with the badge and popup untouched.

## Known limitations

- A from-to shape written with a hyphen, `從-5到5`, reads as a separator every time and stays wrong. It is a documented gap, not a bug to chase.
- Whether a content script can create and prompt a session is unmeasured. It is moot for this design, which routes every prompt through the service worker because that is where the sampling knobs live.
- There is no page-language gate, so a ja or ko page runs the same zh-measured prompt.

## Revisitable

Shipped without, and worth revisiting only on real evidence: a page-language gate, a `chrome.storage.session` result cache, majority voting across repeats, and an in-memory per-page dedupe of answered `(sentence, at)` pairs.
